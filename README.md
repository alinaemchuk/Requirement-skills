# Рев'ю вимог перед тест-аналізом

Набір інструкцій для агента Cursor: skill **requirements-review**. Він перевіряє вимогу за сімома критеріями якості, перш ніж писати тести.

## Що всередині

## Коли викликати

У чаті агента:

- «перевір вимогу …»
- «зроби рев'ю вимог»
- «чи готова вимога до тестування?»
- або явно `/requirements-review`

Встав текст вимоги (або шлях до файлу) у те саме повідомлення.

## Сім критеріїв

1. **Атомарність** — одна вимога описує одну поведінку.
2. **Однозначність** — немає слів на кшталт «швидко», «зручно», «коректно» без визначення.
3. **Повнота** — негативні сценарії та межі або явні питання до BA, якщо їх немає в тексті.
4. **Несуперечність** — немає конфліктів усередині вимоги та з іншими наданими вимогами.
5. **Неповторюваність** — немає дублювання інших наданих вимог.
6. **Тестованість** — до кожного твердження можна написати перевірку.
7. **Реалізовність** — вимогу можливо реалізувати; сумніви без доказу в тексті — питання, не факт.

## Структура звіту

1. **Вердикт** (першим): ✅ Готова до тест-аналізу / ⚠ Потребує уточнень / ❌ Не готова.
2. **Таблиця знахідок:** номер, критерій, цитата, у чому проблема, severity, пропозиція виправлення.
3. **Питання до BA** — те, чого немає в тексті і без власника не виправити.
4. **Що добре** — 1–2 пункти з цитатами (звіт читає BA).

Severity: **Critical** блокує тест-аналіз; **Major** — ризик пропущених або суперечливих тестів; **Minor** — неточність без блокування основного сценарію.

Залізні правила: кожна знахідка — з точною цитатою з вимоги; якщо не впевнений — питання до BA, а не проблема; не вигадуй деталей, яких немає в тексті.

## Як підключити локально

Skill підхоплюється з `.cursor/skills/` цього репозиторію. Окремий сервер чи залежності не потрібні: відкрийте проєкт у Cursor і викличте агента, як вище.
